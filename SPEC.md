# Duplicate invoice candidate review specification

Version 0.22.7. Pure API: `check(raw)` in `src/core.ts`; MCP tool: `duplicate_invoice_check`.

Input is a strict `{records, save?}` object containing 1–1000 strict records. Each has a unique `record_id`, per-record exact `entity_id` and `supplier_id`, type `invoice|credit_note`, invoice number, real ISO date in years 0001–9999, uppercase three-letter currency, and a positive safe-integer total in minor units. Optional display labels never affect matching. Bounded text rejects control characters. Source data is never silently coerced.

The exact scope tuple is `(entity_id, supplier_id, document_type, currency)`, encoded using JSON tuples to avoid separator collisions. Three independent equality buckets compare exact invoice numbers; invoice numbers after ASCII lowercase-to-uppercase and removal of literal space, hyphen, slash and dot (nonempty keys only); and the exact `(total_minor, invoice_date)` tuple. Normalization preserves leading zeros and Unicode. No fuzzy joins, date window, cross-currency comparisons, external history, fraud probability or payment decision.

The report retains source records once, sorted by record ID. Deterministic groups contain a rule, exact scope and match key, complete record IDs, explanation and conflicting source fields. Record summaries identify every overlapping reason. The candidate count is a union, not a sum of group memberships. No amount of financial loss is calculated. There are at most 3N member references and floor(3N/2) groups. Group pages omit member arrays; separate member pages return full source records.

Free use includes full diagnosis, preview pages, CSV and three concurrent saved reports. Pro at $19 or bundle at $39 removes only the saved-count cap. All tiers share a 64 MiB aggregate saved-data bound, the SDK's 10 MiB incoming buffer, 8 MiB response budget, and two previews retained for 30 minutes. Save and delete use the vetted shared file lock. UUIDs and paths are strict; directory creation walks bounded ancestry and rejects symlinks. Writes use private mode 0600 and atomic rename. Reads revalidate source records and recompute evidence.

Acceptance evidence: stdio initialize/list eight tools and actual checks; schema rejection; complete reference conflicts; Unicode, leading-zero and exact-scope negative controls; an independent pairwise oracle over 2000 synthetic batches; 1000-record actual stdio and group-member paging; full free checks after the save cap; positive signed single and bundle license stdio when the operator signer is available; separate-process save-cap concurrency; persistence recomputation, path, symlink and CSV controls; and aggregate storage byte boundaries. All records are synthetic. No paid API, network requests or telemetry.
